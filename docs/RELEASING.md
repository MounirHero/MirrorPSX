# PS5 release: PKG + folder ZIP

Every release ships two distributions of the same native application and its
matching **external shared OpenProspero companion**. There is no automatic ELF
installer/updater. The folder layout follows the homebrew-folder distribution
used by [PS5SX2](https://github.com/Swordpdf/PS5SX2), while retaining MirrorPSX's
own broker, identity and runtime requirements.

## Prepare and build

For a hosted build, configure [the private SDK CI environment](CI.md) and run
**PS5 release artifacts** from GitHub Actions. It produces the same release set
as the local commands below.

Follow [BUILDING.md](BUILDING.md). Build the broker before the native title:

```powershell
.\tools\build-shared-broker.ps1
wsl -d Debian bash tools/build-ps5.sh
```

The broker script reuses the workstation's existing shared configuration in
`%LOCALAPPDATA%/OpenProspero/shared-broker/`. It writes a build-only broker
manifest; the native post-link step records executable and companion hashes in
`build/ps5/release-build.json`. No credential is copied into the release metadata.
Keep the same configuration for other compatible clients; do not generate a new
broker per application or silently replace a running instance.

## Package both formats

```powershell
.\tools\package-ps5.ps1 -Version 10.00
```

Optional parameters: `-SdkRoot`, `-BuildDirectory`, `-OutputDirectory` and
`-ProsperoPath` (an explicit path to the built OpenProspero CLI).
Version uses the SDK's native `NN.NN` format, not a Git commit or a free-form
tag. For this SDK writer, contentVersion is `NN.000.000` using the first version
component; masterVersion keeps the full `NN.NN` value. Advance versions according
to the installer's supported upgrade behavior; changing the minor component
alone does not change the contentVersion generated by this SDK.

`10.00` describes the existing R10 build's native package identity; it is an
example for reproducing that build, not a claim that a new public release exists.

## What the packaging command verifies

1. The native executable has a build receipt and the companion exists.
2. The clean-room `sce_module/libc.prx` matches its recorded SHA-256.
3. The SDK signs the executable and builds the PKG with `--no-companion`.
   This flag excludes the **internal** companion; the app still requires the
   external shared service.
4. The SDK validates and re-extracts the final PKG. Its runtime and executable
   must match the staged files exactly.
5. The ZIP is generated from that re-extracted title, then each archived file
   is checked against the source bytes. Assets, metadata and licenses are
   required; private keys and bundled companion files are rejected.
6. The selected native executable and external broker must match the build
   receipt. The companion license accompanies the ELF.
7. A release manifest and checksums cover the published files. The output
   directory appears only after export succeeds; an existing release directory
   is not overwritten.

Checksums detect corruption; they are not a signature or proof of publisher
identity. Structural validation does not prove installation/launch compatibility.
Test both installation formats on a console before describing either as verified.

## Publish

Upload the **contents of the versioned release directory** together, not the
entire `dist/` folder or a source-code ZIP. Keep the companion with the same
release set even if its code did not change. Do not upload `build/`, build
receipts, `broker_config.hpp`, `token.txt`, pairing keys or local logs.

For example, after reviewing the artifacts and choosing the intended Git tag:

```powershell
gh release create v10.00 .\dist\ps5-v10.00\* --draft --prerelease `
    --title "MirrorPSX 10.00" --notes-file .\docs\release-notes.md
```

Write the release notes first: changes, PKG/folder instructions, companion
requirement, hardware actually tested and remaining limitations. Review the
draft before publishing it. This command is an example; packaging does not
create a tag, upload files or publish a GitHub release automatically.

## Local verification of the exporter

```powershell
python tests/ps5_release_test.py
```

These are fixture-based packaging tests. A development machine without the
native ELF, rebuilt broker and compiled SDK CLI can validate the tooling but
cannot produce an installable release.
